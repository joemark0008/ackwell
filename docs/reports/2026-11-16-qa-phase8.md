## Bugs found

| Id | Severity | Summary | Owner | Status |
|---|---|---|---|---|
| QA-1 | medium | **Graceful shutdown cut off ACKs for messages being stored.** `InboundListener.close()` called node-hl7-server `close()`, which destroys every socket immediately. Repro: trigger that sleeps 1.5 s in the `messages` insert, send 3 messages, `app.close()` while the inserts run → all 3 rows committed with `ack_code = AA`, all 3 senders got a closed connection and no ACK → they resend → duplicates. | backend | **fixed** (lead): the listener tracks in-flight handlers; `close()` refuses new connections, answers AR (nothing stored) to messages that arrive while closing, waits up to 10 s for running handlers to persist and write their ACK, then closes the sockets. Test d2 now asserts AA for all three; d1 (20 concurrent sends + close) still asserts no AA without a row, no duplicates, listener restored on reboot. |
| QA-2 | medium | **Message row stuck on "Processing" after a send while the live stream is open.** Send → the mutation invalidates the list → GET starts → ACK arrives → SSE patches the row to `sent`/AA → the older GET resolves and overwrites it with `processing`. Polling is off while the stream is live, so the row stays stale until another event. Seen in the Playwright run (API logged AA at +0.1 s; UI showed Processing for 20 s). | frontend | **fixed** (lead): `live-state.ts` keeps the newest summary per message id seen on the stream; list query functions overlay fetched rows with a newer streamed version (`updatedAt`). Unit test in `live.test.ts`. |

No critical or high bugs. Observations that are not bugs: node-hl7-server's ACK always uses `|^~\&` even for a custom-delimiter message (MSA-2 is still correct); in Vite dev mode the first open of the Monaco dialog after a restart can take up to a minute (transform of the lazy chunk), production builds do not have this.

## Coverage gaps / risks

- **Live site, signed in:** the Playwright flow has not been run against https://ackwell.joemarkgimeno.com. Sign-up is disabled, the lead was not allowed to insert a user into the live database, and no admin password is available to the session. Command once a login exists: `cd e2e && BASE_URL=https://ackwell.joemarkgimeno.com QA_EMAIL=… QA_PASSWORD=… MLLP_PORT=6103 ./local-stack.sh test` (the flow creates and deletes its own channels; inbound deliveries go to `/health` and show as failed unless `WEBHOOK_URL` points at a reachable receiver).
- Scenario 2 with the database *down* (not a failing insert) and scenario 11 with a real SIGTERM to a separate process are not automated; `app.close()` runs the same shutdown hooks.
- Test d1 is a race by design: the split between AA / AR / reset differs per run, every assertion holds in each case.
- The debug-log capture covers the pino stdout setup used in tests, not pino-pretty (`NODE_ENV=development`).
- Running the test suite rebuilds `packages/schemas/dist`, which the live dev container shares through the bind mount; Vite and `nest --watch` see the folder disappear for a moment (type errors in the log, page errors for a second). After a suite run, touch a file under `apps/api/src` if the live API log shows "Found N errors" and no restart.
- The real HL7 share is still not mounted (`/mnt/hl7share` is a local folder), so file transport is only tested with temp folders.
- Inbound TLS private key stored in clear in `channels.config`; handshake failures not logged (Phase 7 follow-ups, unchanged).
